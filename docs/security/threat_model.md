# Threat Model: Stalvi Application

## 1. System Overview
Stalvi is a local-first mobile application (iOS/Android). All sensitive financial data is stored locally on the device. The app communicates with the internet solely to fetch daily currency exchange rates.

## 2. Assets to Protect
1. **User Financial Data:** Transaction history, account balances, budgets.
2. **Encryption Keys:** The SQLCipher database key.
3. **Authentication Data:** User PIN or biometric unlock state.
4. **Exported Files:** PDFs, CSVs, and JSON backups generated by the user.

## 3. Threat Agents
- **Physical Attacker:** Someone who gains physical access to the unlocked or locked device.
- **Malicious Application:** Malware installed on the same device attempting to read Stalvi's memory or storage.
- **Network Eavesdropper (MitM):** Attacker intercepting network traffic (low risk due to no cloud sync, but relevant for API calls).

## 4. STRIDE Analysis & Mitigations

| Threat Category | Specific Threat | Mitigation Strategy |
| :--- | :--- | :--- |
| **Spoofing** | Attacker bypasses the app lock screen. | Enforce OS-level Biometrics (`local_auth`) or secure PIN. Implement timeout locks. |
| **Tampering** | Modifying the local SQLite database file directly. | Database is encrypted at rest using **SQLCipher**. Without the key, the file is unreadable and untamperable. |
| **Repudiation** | User claims transactions were deleted maliciously. | App uses a 30-day "soft delete" (Trash) mechanism to prevent accidental or unauthorized immediate data loss. |
| **Information Disclosure** | OS takes screenshots of the app for multitasking, leaking balances. | UI blurring implemented at the app lifecycle level when moving to the background. "Discreet Mode" hides balances by default. |
| **Information Disclosure** | Attacker extracts database via root/jailbreak. | The database key is stored in the hardware-backed Keystore/Keychain via `flutter_secure_storage`. Root access makes extraction harder but not impossible; SQLCipher provides the best defense here. |
| **Denial of Service** | Corrupted database prevents app startup. | Implement an automated backup mechanism (Encrypted JSON) allowing users to restore data if the main DB corrupts. |
| **Elevation of Privilege** | Not highly applicable (no cloud backend/roles). | Rely on OS sandboxing. Do not request unnecessary device permissions. |

## 5. Third-Party Risks
- **Exchange Rate API:** Ensure API requests use HTTPS. Never send user data in the request payload. Only GET public rates.
